### Findings

- The visible screenshot issue is consistent with the runtime road overlay path in `TenerifeGeoRoadLayers`, not the baked Puerto `terrain=real` PBR terrain path.
- Runtime road surfaces are currently opaque procedural ribbon meshes with procedural Voronoi/noise color and synthetic lighting. They have no photographic albedo, normal, AO, roughness, displacement, curb detail, dirt decals, tire marks, or terrain material masks.
- The repo already has the better long-term direction for `terrain=real`: baked terrain GLB plus generated 2048 road/albedo/normal/ORM textures, with road ribbons kept as debug or optional close-range overlays.
- The next visual quality step should not be more procedural line art. It should be a bake-first material upgrade: real PBR road texture sets, road/shoulder masks, edge dirt blend, decals, and optional close-range geometry only where needed.
- Runtime physics authority should stay on terrain/ground. Photoreal road detail should remain visual-only unless a later gameplay requirement explicitly changes collision.

### Recommended Implementation Direction

1. Keep `terrain=real` defaulting to baked road material and treat `roads=mesh`/`roads=both` as debug or close-range enhancement.
2. Replace procedural cobblestone/dirt rendering in the runtime road surface pass with PBR texture sampling if the overlay remains visible.
3. Add real road material assets with documented source/license and texture budget: albedo, normal, roughness/ORM, AO, optional height.
4. Use road masks for core road, shoulder, and disturbed terrain edges rather than clean rectangular ribbon edges.
5. Add decals for cracks, patched stones/asphalt, sand/dust accumulation, curb breaks, drain covers, tire marks, and pedestrian path wear.
