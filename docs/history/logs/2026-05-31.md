# 2026-05-31

## Run Jump Landing Recovery

- Investigated the reported regression where holding run, pressing jump, and
  landing while still moving could leave the imported player visual in the
  one-shot jump/free-fall pose until movement input changed.
- Updated the player movement polish task notes with Phase 6 for run-jump
  landing recovery.
- Extracted grounded-state resolution into `resolvePlayerGroundedState` so the
  render loop has a tested decision boundary for post-jump suppression, grounded
  hysteresis, and descending landing recovery.
- Kept the existing post-jump suppression so the upward impulse is not cancelled
  by an immediate ground ray, but allowed descending landing to use the looser
  ground threshold after that suppression window.
- Preserved XZ jump momentum by keeping full target speed and reducing airborne
  acceleration instead of reducing target speed.
- Added regression coverage for the grounded-state cases that drive run+jump
  animation recovery.

## Jump Clip Completion Recovery Follow-Up

- Reinvestigated after user feedback that the first fix did not resolve the
  visible stuck pose.
- Identified the visual-only failure mode: `AssetPlayerVisual` starts the
  imported `Jump` animation as a non-looping one-shot, but if `isAirborne` is
  already false and `isMoving`/`isSprinting` do not change, React has no prop
  change to rerun animation selection.
- Added active animation state tracking and an `onAnimationGroupEndObservable`
  handler for the jump clip. When the jump clip completes while the latest flags
  say grounded, the visual requests one recovery pass and resumes walk/run/idle.
- Kept the completed jump pose while the controller still reports airborne, so
  a real long jump still waits for landing before switching to locomotion.
- Added pure tests for the completed jump recovery predicate in
  `playerAnimationRegistry.test.ts`.
